## EX-04 independent implementation review - 2026-09-20 UTC

**Independent implementation complete; hosted and cross-device acceptance BLOCKED / NOT RUN.** The

environment files, deployments, or running processes.

### Confirmed defects and repairs

1. The API returned `{ url, expiresInSeconds }`, but the web's strict shared schema allowed only
   `url`; valid report previews could therefore fail validation. The contract now includes the bounded
   lifetime, both preview screens refresh the URL before expiry, and the API response is
   `Cache-Control: private, no-store`.
2. Worker screening converts a mislabeled report to a storage-only prescription. The report route
   then correctly returns owner-scoped 404, but the review UI previously rendered only “Report
   unavailable.” It now performs an owner-scoped document fallback and presents a storage-only state
   with a link to the document; non-owners still receive the generic unavailable state.
3. `/health` called PostgreSQL/Redis while the specification defined it as liveness, and root HTML
   claimed readiness. `/health` is now process liveness, root copy is accurate, and public `/ready`
   checks PostgreSQL, Redis, and that the configured Supabase bucket exists and is private. Gemini is
   deliberately not implied by API readiness because processing readiness belongs to the worker.
4. Raw client `x-request-id` values were reflected into responses and report jobs, and 429 responses
   omitted the correlation field. The API now accepts only a bounded log-safe identifier or generates
   a UUID, uses it in all safe errors/rate-limit responses, and passes the same value to report jobs.
5. Multer errors other than file-size overflow fell into the generic 500 path. They now return a safe
   `INVALID_UPLOAD` 400; size overflow remains `FILE_TOO_LARGE` 413.
6. Logout relied only on navigation/remount to discard private React Query state. It now explicitly
   clears the active query client before redirecting, while the authenticated layout remains keyed by
   verified user ID.

### Finding, patch contract and scope

**D-03 / outcome: fixed at the application boundary.** A verified caller could PUT their own medication with another patient's prescription ID (or a report/missing ID). `updateMedication` checked the target medication owner but passed the supplied link directly to Prisma. The HTTP route's UUID validation did not authorize the linked document. The existing create path already checked document ID, patient and `PRESCRIPTION` type.

The narrow fix extracts that existing predicate into `validatePrescriptionLink` and calls it from create and update. Update first checks the medication owner, then the replacement link, before any medication write. It retains `400 INVALID_PRESCRIPTION / Prescription not found.` for foreign, missing and wrong-type documents, without revealing which case occurred. A foreign/missing medication still returns 404 first. Patient identity still comes from authenticated response locals and the patient lookup, never submitted patient fields.

Compatibility: this is the existing full PUT contract, not PATCH. `name` remains required; omitted or null `prescriptionId` both clear the link; an omitted status preserves the old status. ### Runtime contract and root-cause fixes

- Comparisons use only reviewed values. A deliberately cleared reviewed numeric/text/unit/range field no longer falls back to the AI guess. Aliases are exact; qualifiers such as fasting/random are not erased. Unsupported analyte/unit pairs and known lab/method/specimen differences remain separate. Current persisted context supplies laboratory/hospital only; method/specimen remain unknown, so clinical comparability is explicitly uncertain.
- Supported conversions are hemoglobin g/dL↔g/L; glucose mg/dL↔mmol/L; and total/HDL/LDL cholesterol mg/dL↔mmol/L. Different mass-to-molar analytes do not share a generic factor. Source observations/units/ranges are retained; numeric values and parseable bounds convert together. These are approximate conventional unit factors, not clinical thresholds. Decimal-aware arithmetic avoids routine binary subtraction artefacts; source doubles are not rewritten.
- Date-only report dates are the clinical ordering key, displayed with UTC. Unknown dates have no fabricated fallback and are not plotted. `createdAt` and ID order only stabilize ties; upload time does not replace clinical time. Distinct same-day tests remain, but no within-day clinical ordering/change is inferred. Duplicate imports require matching bytes and matching reviewed observation/context/slot, not simply a shared date/test name.
- Bounded/qualitative/missing values stay visible in the table and are not plotted as zero. A shared band requires every plotted point's known equivalent range in the displayed unit. Missing or different bounds suppress the band and explain why. Flags come from source annotations, not guessed reference interpretation. Extreme finite inputs that overflow chart coordinates render an unavailable-scale state.
- Individual summaries use the report directly; they create no unwanted episode. Both scopes share `MedicalSummary`, `SummaryStore`, the `episode-summary` queue and `summarize-reviewed-sources` job. The legacy `EpisodeAnalysis` model/data remain intact; ungrounded legacy summaries are not presented as current validated results.
- Gemini receives bounded structured facts, not profile fields, Storage objects or file URLs. Application code calculates comparisons and creates fact text. Gemini selects fact IDs only; strict validation rejects invented IDs, duplicate selections, fabricated values, units, prose and urgency claims. Application-owned facts, limitations and cannot-assess text are rendered. This intentionally constrained summary is not a free-form clinical interpretation.
- Queued payloads, provider output, summary storage writes, episode/trend responses and report-page responses are runtime validated. TypeScript casts in controlled test doubles are documented as mocks. Internal union narrowing after a validated status check is not treated as external validation.
- API and worker fingerprint the full reviewed source snapshot, eligibility, document/extraction versions, source update times, dates, ranges/units/flags, episode membership/context, configured model and prompt/config versions. One unique scope key gives one current summary row. A generation counter and random claim token bind each job to that row/version.
- Source triggers and publication transactions take the same patient-row lock. No database transaction spans a Redis or Gemini call. The final write checks fingerprint/generation/token/status and recomputes the current source snapshot under the lock. Corrections or membership changes during processing discard the old result rather than publish it. Patient-wide invalidation is intentionally conservative: even an unrelated source write can require regenerating that patient's summaries. Direct reassignment of ownership/source foreign keys is not an application workflow and requires a separate controlled data-repair procedure.
- Statuses are `QUEUED`, `PROCESSING`, `COMPLETED`, `FAILED`, `STALE`. Provider calls have a 45-second timeout; claims lease for 75 seconds; at most four processing claims/queue attempts; transient backoff starts at two seconds. Inputs are capped at 30 reports/500 observations, 120,000 serialized input characters and 30 selected facts. Regeneration has a 30-second cooldown.
- Same-source completed summaries are reused even on repeated force requests. Active claims are not superseded. A deliberate retry after an expired lease or a queued state stranded for two minutes creates a new fenced generation. The old job can no longer publish. There is no automatic global summary replay: after a worker crash or missing job, the patient/operator may need to use retry once the delay expires. This is documented recovery, not an auto-reconciliation claim.
- Polling is read-only, consumes the returned result, uses the plural episode analyses endpoint, stops on terminal/error states and pauses after two minutes. Long waits explain local worker availability. Corrections invalidate report/dashboard/episode/summary queries. Existing authentication cache clearing remains the cross-account boundary; no browser persistence was introduced.
- No validated clinical red-flag registry exists. The UI explicitly says clinical significance/urgency cannot be assessed; patient review is not clinician certification. Source abnormal/critical annotations are displayed as provenance-bearing annotations, not autonomous triage or treatment advice.
